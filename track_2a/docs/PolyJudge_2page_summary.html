PolyJudge: Track 2A short method description

UZH challenge: detecting cross-lingual semantic differences in Swiss government websites. Team: Solo, Hasan Sarı. Repository: https://github.com/hasanssr/polyjudge-swissgov-rsd

1. Problem and task

For an English government web page and its German, French or Italian version, predict a score in [0, 1] for every whitespace token on both sides (how strongly the token belongs to a semantic difference), and -1 on ASCII punctuation tokens. Data: SwissGov-RSD (Wastl, Vamvas, Sennrich; CC-BY-4.0). Metric: the organizers' token-level Spearman, pooled per language, macro average over de/fr/it. No training data is used; Apertus is used by prompting only (CSCS Inference API, models swiss-ai/Apertus-v1.5-70B and -8B). The project name comes from the original multi-agent idea (M2, with a "judge" role); the submitted main system M1 is alignment-first.

4. Three key findings

  1. Almost all of M1's score comes from the model-free base. M1 (0.276) is 0.003 above B0 (0.273); the verifier adds only 74 flagged tokens (5 086 vs 5 012 predicted > 0). The Apertus contribution on top of the model-free base is small. M1 is ahead of M0 by +0.063, but the lower bound of that interval is +0.001.
  2. Simple prompting over-flags, and LLM spans were not precise enough to help. M0 marks 33 616 tokens as nonzero where the gold has 15 840. On the 78 development-pool documents (cross-validation), flags accepted by the 70B verifier had token precision 32.1 %, below the roughly 40 % needed to raise pooled Spearman over a base that is 92 % ties; the gain was -0.021 [-0.043, +0.021].
  3. More agents did not help. M2 and M3 did not beat M1 (both 0.256), and their intervals against M0 include zero. In the ablation, debate-style agents had lower flag precision (24.3 %) than the verifier alone on deterministic candidates (45.4 %, on 6 chunks only; 32.1 % on all 78 documents).

5. Protocol and honesty notes

  • Splits. prompt_pool (78 documents) is the only data used for tuning prompts, examples and thresholds. dev_select (15 documents, 5 chunks, a subset fixed by a budget rule) screened the five candidates; its results are noisy (every interval against M0 contains zero). dev_final was locked and never opened.
  • Preregistration. Written before the first dev_select run, with code hash and decision rules. Three dated addenda: owner confirmations (no rule changed), a single-flight fix in the LLM client (new code hash, same prompts and parameters), and the rules for the final ranking, written before any test prediction.
  • Test run once. Test predictions were generated from inputs only, hashed, and replayed from the cache with identical hashes. Only after that were the public test labels opened, with the written permission of the challenge owner (UZH, e-mail of 5 October 2026; docs/owner_confirmations.md), and each candidate was scored exactly once.
  • Selection. The main system was picked by the preregistered rule: highest test macro Spearman among M0 to M3 (B0 never eligible). M1 was 0.0198 ahead of M2, more than the 0.005 tie margin.
  • Stability. On dev_select the order was M2 > M1 > B0 > M3 > M0; on test it was M1 > B0 > M2 = M3 > M0. Small samples reorder close candidates.
  • Packaging after the freeze changed where inputs, few-shot examples and the scorer come from, not any algorithm, prompt or parameter. All five methods reproduce the frozen predictions byte for byte offline (docs/code_changes_after_freeze.md).

6. Limitations

  • Small evaluation sets: 15 dev_select documents; cross-validation on 78 prompt_pool documents with wide intervals (macro 0.425, [0.257, 0.550] for the model-free aligner); 56 test documents per language.
  • French is weak for every method (0.079 to 0.131); the macro score is carried by German and Italian.
  • The SwissGov-RSD labels were re-annotated in April 2026. Published numbers (best macro 18.1, Spearman × 100) use the full benchmark and possibly other labels, so they are not comparable with ours.
  • make eval (the organizers' scorer inside the image) was not executed in the verification of the repository.
  • M2's dev_select run cannot be replayed from the cache (20 of 86 Compare requests missing, because identical in-flight requests were sent separately); the fix is single-flight merging, used for the test run.
  • Predictions assume whitespace tokens of the given tokenized text and -1 on ASCII punctuation only; the format rules were relayed to us and not re-checked against the organizers' script.
